# План реализации: Калькулятор себестоимости

## Контекст

Разработка одностраничного веб-интерфейса с 3-мя калькуляторами себестоимости поставки для внутренней команды. Проект состоит из Next.js (React) фронтенда и FastAPI бэкенда, использующего Google Sheets как источник справочных данных.

---

## Общая архитектура

```
/
├── apps/
│   ├── web/              # Next.js фронтенд
│   │   ├── app/
│   │   │   ├── layout.tsx
│   │   │   └── page.tsx           # Главная страница с вкладками калькуляторов
│   │   ├── components/
│   │   │   ├── Calculator.tsx     # Компонент калькулятора
│   │   │   ├── FormInputs.tsx     # Поля формы
│   │   │   └── ResultBlock.tsx     # Блок результата с копированием
│   │   └── lib/
│   │       └── api.ts              # Клиент API
│   └── api/              # FastAPI бэкенд
│       ├── main.py                    # FastAPI приложение
│       ├── models/                    # Pydantic модели
│       ├── calculators/               # Модули расчётов
│       │   ├── calculator1.py
│       │   ├── calculator2.py
│       │   └── calculator3.py
│       ├── repositories/
│       │   └── sheets_repo.py        # Google Sheets + кэш
│       └── requirements.txt
├── docker-compose.yml
├── .gitignore
└── README.md
```

## Этап 1: Инициализация проекта и инфраструктура

### Подэтапы

1.1 **Создание структуры папок и файлов**
- Создать папки `apps/web`, `apps/api`
- Создать файлы: `docker-compose.yml`, `.gitignore`, `README.md`

1.2 **Настройка Docker Compose**
- Создать сервисы: `web` (Next.js), `api` (FastAPI), `redis`
- Настроить env-переменные

1.3 **Инициализация Next.js проекта**
- `npx create-next-app@latest apps/web` с TypeScript
- Установить зависимости: MUI, react-hook-form, zod, @hookform/resolvers

1.4 **Инициализация FastAPI проекта**
- Создать `apps/api/main.py`
- Создать `apps/api/requirements.txt`

**Используемый skill:** `agents-md` для создания AGENTS.md с описанием структуры проекта

**Проверка:**
- Проверить, что `docker-compose up --build` запускается без ошибок
- Проверить доступность веб-страницы на `http://localhost:3000`
- Проверить доступность API на `http://localhost:8000/docs`

---

## Этап 2: Backend - Базовая структура API

### Подэтапы

2.1 **Создание Pydantic моделей** (`apps/api/models/`)
- `CalculatorRequest.py` - модель запроса с обязательными/опциональными полями
- `CalculatorResponse.py` - модель ответа с результатом расчёта

2.2 **Настройка FastAPI эндпоинта** (`apps/api/main.py`)
- Создать POST `/calculate` endpoint
- Добавить базовую валидацию через Pydantic

2.3 **Создание заглушек калькуляторов** (`apps/api/calculators/`)
- `calculator1.py`, `calculator2.py`, `calculator3.py` с базовым интерфейсом
- Временный возврат тестовых данных

**Используемые skills:** `react-best-practices` (для Python/FastAPI аналогичных паттернов)

**Проверка:**
- Запустить Docker контейнеры
- POST запрос на `/calculate` с валидными данными возвращает 200 OK
- POST запрос с невалидными данными возвращает 422

## Этап 3: Frontend - Базовый UI с вкладками

### Подэтапы

3.1 **Создание компонента вкладок** (`apps/web/components/`)
- Использование MUI Tabs для переключения "Калькулятор 1/2/3"
- Состояние `activeTab` (1, 2, 3)

3.2 **Базовый лейаут страницы** (`apps/web/app/page.tsx`)
- Два основных блока: "Исходные данные" и "Результат расчёта"
- Размещение в одну строку (desktop) или столбец (mobile)

3.3 **Стилизация по требованиям PRD**
- Лаконичный дизайн, один акцентный цвет
- Скругление углов, мягкие тени
- Типографика с 2-3 кеглями

**Используемый skill:** `react-best-practices` для корректной структуры компонентов

**Проверка:**
- Страница загружается без ошибок в браузере
- Вкладки переключаются, активная выделяется акцентом
- Лейаут корректно отображается на разных экранах

## Этап 4: Frontend - Форма ввода

### Подэтапы

4.1 **Настройка react-hook-form + Zod** (`apps/web/lib/`)
- Создать схему валидации Zod для обязательных полей
- Интеграция с react-hook-form

4.2 **Создание полей формы** (`apps/web/components/FormInputs.tsx`)
- Поля: Материал (select), Порт отправления (select)
- Пункт назначения (select), ЖД станция (select, условно)
- Количество (числовое), Размер контейнера (select)
- Цена за кг (числовое)

4.3 **Обработка логики ЖД станции**
- Поле активируется/деактивируется после выбора пункта назначения
- Зависимость от ветки маршрута (Владивосток → ЖД доступно)

4.4 **Форматирование ввода**
- Разделитель дробной части запятая
- Placeholder внутри полей

**Используемый skill:** `react-hook-form-zod` для корректной настройки форм

**Проверка:**
- Обязательные поля валидируются при отправке
- ЖД станция корректно блокируется/разблокируется
- Форматирование чисел с запятой работает

## Этап 5: Backend - Интеграция с Google Sheets

### Подэтапы

5.1 **Настройка Google Sheets API** (`apps/api/repositories/`)
- Создать `sheets_repo.py`
- Настроить аутентификацию через service account

5.2 **Создание кэш-слоя**
- Redis подключение
- TTL для справочников

5.3 **Загрузка справочников из Google Sheets**
- Таблица: город РФ → порт РФ
- Таблица: порт Китай + порт РФ + контейнер → фрахт (USD)
- Таблица: диапазоны таможенного сбора
- Прочие справочники по материалам, ставкам пошлины и т.д.

**Используемый skill:** `agents-md` для документации структуры данных

**Проверка:**
- Данные успешно загружаются из Google Sheets
- Кэш работает, повторные запросы используют кэшированные данные
- Redis хранит справочники

## Этап 6: Backend - Реализация бизнес-логики Calculator1

### Подэтапы

6.1 **Реализация логики маршрутов**
- Определение порта РФ по городу назначения
- Логика веток: Владивосток (ЖД) vs Новороссийск/СПб (авто)

6.2 **Реализация финансовых расчётов** (по формулам из PRD)
1. Сумма закупки (CNY → RUB)
2. Фрахт (USD → RUB)
3. Таможенная стоимость
4. Пошлина
5. Таможенный сбор (по диапазонам)
6. НДС
7. Брокер
8. Вывоз/доставка
9. Банковская комиссия
10. Полная себестоимость и за 1 кг

6.3 **Формирование текста результата**
- Форматирование чисел с разделителями тысяч
- Структура результата как в примере из PRD

**Проверка:**
- Расчёт совпадает с эталонными значениями
- Ветка маршрута корректно выбирается
- Текст результата форматируется правильно

## Этап 7: Frontend - Интеграция с API

### Подэтапы

7.1 **Создание API клиента** (`apps/web/lib/api.ts`)
- Функция для отправки на `/calculate`
- Обработка ошибок

7.2 **Связывание формы с API**
- При клике "Рассчитать" отправка данных
- Отображение результата в блоке результата
- Обработка ошибок и отображение текста ошибки

7.3 **Кнопка "Сбросить"**
- Очистка всех полей формы
- Очистка блока результата

**Используемые skills:** `react-best-practices` для паттернов загрузки данных

**Проверка:**
- Кнопка "Рассчитать" вызывает API и показывает результат
- При ошибке валидации показывается сообщение
- Кнопка "Сбросить" очищает форму и результат
